# AIRUSS — Центр ошибок и исправлений

## Для пользователей
На главной странице сайта: «🐞 Сообщить об ошибке» или раздел «Поддержка».
Форма: https://github.com/ivan19326/airuss-browser-downloads/issues/new?template=bug_report.yml
Отправка требует аккаунта GitHub. Не публикуйте секреты, cookies, личные данные, приватные переписки.

## Автоматическая сортировка
GitHub Actions `issue-triage.yml` запускается при открытии, изменении или повторном открытии Issue.
Ставит метки `area:website`, `area:voice`, `area:ai`, `area:ui`,
`area:installer`, `area:performance`, `area:security`, `area:other`,
а также приоритет и `status:needs-review`.
Это классификация по правилам (без LLM), возможны ошибки; нужна ручная проверка.

## AI-подготовка исправления сайта
Только для ошибки сайта и только с меткой `ai-fix-approved`, добавляемой человеком.
При добавлении этой метки GitHub Actions `ai-site-fix.yml` запускает `scripts/ai_site_fix.py`.
Скрипт проверяет Issue, запрашивает модель OpenAI и может изменить **только index.html**
в отдельной ветке, после чего создаёт draft Pull Request. Изменения НЕ объединяются
автоматически, ничего не выкладывается без ручного решения.
Браузерное приложение и AIRUSS Mobile этим скриптом не затрагиваются.

### Как включить AI
1. Добавить `OPENAI_API_KEY` как **GitHub Actions repository secret** в публичном
   репозитории `airuss-browser-downloads`, НЕ в Issue, не в чат и не в файлы.
   Ключ отдельно тарифицируется провайдером API.
2. В GitHub Actions убедиться, что действия разрешены и workflow может создавать PR:
   Settings → Actions → General → Workflow permissions / Allow GitHub Actions to create and approve pull requests.
3. Для безопасной тестовой ошибки сайта добавить метку `ai-fix-approved`; проверить
   выполнение workflow и вручную проверить открытый draft PR.
4. Перед объединением проверять фактическую работу ссылки загрузки, доступность,
   приватность, diff HTML и откат при проблемах.

### Важные ограничения
- Не утверждать, что AI сам устраняет любой дефект.
- Скрипт ограничен **только сайтом**, не исправляет ошибку в установщике/браузере.
- Жалобы — недоверенный ввод. AI-патч в draft PR обязательно проверяется человеком.
- Серьёзные сообщения о безопасности НЕ отправлять как публичные Issues.
- Если ключ API отсутствует, агент ничего не меняет.
- Если PR workflow запрещены настройками GitHub, их должен разрешить администратор.
